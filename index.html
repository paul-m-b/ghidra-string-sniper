Ghidra String Sniper

Automated String-Based Library Identification for Reverse Engineering

Our team: Paul Biernat, Jack J, Jack Angelicho, Jaden Bowers, Cory Tsang

Developed during Fall 2025 – Spring 2026

Why This Matters

Reverse engineers often spend hours rediscovering known libraries due to stripped binaries. Automating identification reduces analysis time, improves accuracy, and allows analysts to focus on novel or security-relevant code.

Tech Stack

Ghidra (Java), Python backend, LLM integration, Sourcegraph API

Introduction / Proposal

Reverse engineering proprietary binaries is often hindered by stripped symbols, making it difficult to quickly understand a program’s structure and behavior.

Even stripped binaries often contain useful strings that reveal functionality, libraries, or protocols. Sourcegraph enables large-scale search across public repositories to map these strings to real implementations.

System Overview

Proposed Solution

  1. Extract strings from binary
  2. Search Sourcegraph
  3. Use LLM correlation
  4. Suggest symbols/structures

How It Works

  1. String extraction
  2. Sourcegraph search pipeline
  3. LLM ranking
  4. Results returned to analyst

Overall Goal

Reduce redundant analysis, improve identification of known components, and accelerate early-stage binary understanding.

Usage Guide

Prerequisites

  • Ghidra installed
  • Target binary
  • OpenRouter API key

Installation

  1. Clone repository
  2. Add API key to TOKEN file
  3. Run Windowsdeploy.bat or LinuxBuildInstall.sh

Running

  1. Open Ghidra project
  2. Import binary
  3. Enable plugin in CodeBrowser
  4. Run analysis from UI panel

Interpreting Results

  1. Select extracted string
  2. Review LLM ranking
  3. Inspect matched repositories
